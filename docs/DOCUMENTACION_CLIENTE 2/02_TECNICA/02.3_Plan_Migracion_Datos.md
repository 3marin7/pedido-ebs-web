# Plan de migración de datos
## Sistema EBS

**Revisión:** 21 de octubre de 2026
**Estado:** borrador; ninguna migración queda acreditada por este documento
**Cliente, ambiente, origen y responsables:** pendientes de confirmar

> El repositorio contiene código cliente para consultar y modificar datos de Supabase, pero no contiene aquí un esquema versionado completo ni archivos de origen, inventario o scripts de migración ejecutados. No se conocen volumen, formatos, fechas, duración ni resultados. No cargar datos productivos usando supuestos.

## 1. Alcance a definir

Antes de planear una carga, acordar por escrito:

- Orígenes de datos, titularidad, periodo, volumen y categorías de información personal.
- Entidades que se migrarán y cuáles quedarán fuera.
- Proyecto Supabase destino, ambiente y versión del esquema.
- Reglas de normalización, duplicados, datos incompletos y resolución de conflictos.
- Responsables técnicos y del negocio, ventana y procedimiento alternativo.
- Aprobación de privacidad, seguridad, tratamiento y retención.

## 2. Referencia técnica del destino

El código consulta nombres de tablas como `productos`, `clientes`, `facturas`, `detalles_factura`, `abonos`, `pedidos`, `historial_inventario` y `user_profiles`, entre otros. La lista no define las columnas o restricciones. Obtener el esquema real de Supabase por migraciones aprobadas o introspección controlada antes de preparar el mapeo.

## 3. Etapas propuestas

| Etapa | Actividad | Evidencia para cerrar |
|---|---|---|
| Inventario | Recibir y clasificar archivos aprobados | Catálogo de fuentes, fechas, volúmenes y dueño |
| Mapeo | Relacionar cada campo origen con el destino | Mapeo firmado con reglas y exclusiones |
| Preparación | Limpiar datos y resolver duplicados con el cliente | Archivos normalizados y log de cambios |
| Ensayo | Cargar en un ambiente no productivo | Log de carga y lista de errores |
| Conciliación | Comparar conteos, relaciones y valores de negocio | Resultados revisados por el cliente |
| Aprobación | Aceptar ventana, copia, rollback y criterios | Aprobación escrita de responsables |
| Carga final | Ejecutar con el procedimiento aprobado | Registro de ejecución y versión de scripts |
| Cierre | Verificar operación y documentar incidencias | Acta de aceptación o plan de corrección |

## 4. Controles mínimos

- Conservar los originales y limitar el acceso a quienes estén autorizados.
- Usar un ambiente de prueba y datos anonimizados cuando sea posible.
- Registrar versión de script, conteos de origen/destino, errores y correcciones; nunca ocultar o descartar errores silenciosamente.
- Validar claves, relaciones, importes, saldos e inventario con reglas aprobadas para los datos reales.
- Tomar una copia recuperable según el plan vigente y ensayar la restauración antes de intervenir producción.
- Detener la carga si los resultados exceden umbrales acordados; el rollback se define y prueba antes del corte.

## 5. Criterios de aceptación

Los umbrales de completitud, exactitud, tiempo de indisponibilidad y tolerancia a diferencias quedan pendientes de acuerdo. Registrar cada criterio, método de cálculo, responsable y evidencia. No declarar porcentajes o resultados de éxito hasta medirlos.

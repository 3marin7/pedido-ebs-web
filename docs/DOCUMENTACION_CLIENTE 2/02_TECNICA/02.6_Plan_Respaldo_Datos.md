# Plan de respaldo y recuperación
## Sistema EBS

**Revisión:** 21 de octubre de 2026
**Estado:** propuesta pendiente de configuración, contratación y prueba
**Proyecto Supabase y responsables:** por identificar

> En el repositorio no hay configuración de backups/restauración ni evidencia de ejecuciones. La consola y el contrato del proveedor no se revisaron. No se puede afirmar frecuencia, retención, ubicación, costo, disponibilidad, RPO/RTO ni que los datos estén respaldados. Este documento define lo que falta verificar; no es una garantía de recuperación.

## 1. Alcance que debe confirmarse

Identificar las bases de datos, archivos, imágenes y código que se consideren parte del servicio, sus titulares y los responsables autorizados. Determinar qué opciones de backup ofrece el proyecto Supabase contratado y qué activos requieren exportación adicional. No asumir que el almacenamiento de imágenes o el código fuente están incluidos en la copia de la base de datos.

## 3. Procedimiento operativo propuesto

1. Obtener aprobación del titular del proyecto antes de cualquier exportación o restauración.
2. Registrar servicio, ambiente, fecha, responsable, alcance y evidencia de cada copia.
3. No almacenar claves en el repositorio ni en variables `VITE_`; custodiar credenciales de administración en un gestor autorizado.
4. Probar restauración en un ambiente separado antes de declarar recuperabilidad.
5. Validar integridad y acceso después de la restauración, sin exponer datos personales.
6. Documentar incidentes, tiempos observados, acciones correctivas y fecha de siguiente prueba.

## 4. Objetivos y compromisos

Los valores de RPO, RTO, retención, frecuencia, disponibilidad, soporte y recuperación deben acordarse con el cliente y confirmarse con el proveedor. No se especifican cifras hasta contar con esa evidencia y una oferta/contrato aplicable.
